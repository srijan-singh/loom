Issue #8 UI reference

App shell, first-launch onboarding, and home dashboard for Loom. Every screen below is live: switch states, change the provider, and click through the rail to see what each widget should do.

Source: srijan-singh/loom#8. Route names, widget names, and API calls follow the issue.

Layout, spacing, states, and copy are the spec. The font, icons, and logo mark are placeholders you can swap. Where this file departs from the issue text, it is listed under Decisions and checklist.

Design tokens

Named after natural dyes: a single indigo accent, with madder, lichen, and weld for status. Use the theme toggle (left) to see both modes. Never hardcode hex in widgets; read from the theme.

Type

Instrument Sans for the interface, JetBrains Mono for code, IDs, and routes. Both are available through the google_fonts package. Sentence case everywhere.

Provider

State

  • selectedProvider, apiKey, selectedModel
  • testState: idle, testing, valid, rejected, unreachable
  • Pick one approach (setState or Riverpod) and use it for the whole app

Behavior

  • Test key calls POST /llm/test. On success it fills the model list from the provider
  • Save and continue runs the test first if the key is untested, and saves only on success
  • Save writes the key to flutter_secure_storage; provider, model, and the onboarding flag go to shared_preferences
  • Then go to /onboarding/mcp-setup, or /dashboard while that route is a stub

Errors and copy

  • Results are inline, never a SnackBar. A rejected key stays visible next to the field
  • A rejected key and a network failure use different copy, so nobody re-pastes a good key
  • Empty key: "Enter your API key."
  • Model list is not hardcoded. Keep the custom ID link as a fallback

Data

  • GET /skills count, GET /mcps count where status is CONNECTED, GET /agents count
  • GET /sessions?limit=5&sort=recent for the list
  • GET /events (SSE) keeps running rows live: a finished session flips its status without a refetch
  • All calls go through api_client.dart

Layout

  • Greeting is time-based: morning before 12, afternoon before 17, evening after
  • Stat cards are 3 columns and are tappable: each opens its Library tab
  • Session row: status icon and word, workflow name, agent count, relative time (via intl)
  • Quick start sits below the list, one primary button

States

  • Loading: skeleton cards and three skeleton rows, no spinner
  • New user: setup checklist replaces the stat row; empty sessions get an invitation, not an error
  • One failing endpoint shows an error inside its own stat card, not a failed page
  • Engine down or starting: full-window state, shell content never renders empty counts

Shared components

The six widgets the issue asks for, plus the states each needs. Build these once; the Library and Canvas issues reuse them.

LoomButton

Primary, secondary, destructive. Add a ghost for low-emphasis actions. One primary per view. Keep buttons enabled and respond on tap rather than disabling.

LoomTextField

Label above, 36 high, obscure toggle when needed. Errors sit below the field and stay until the value changes.

That key was rejected. Check it and try again.

StatCard

Count and label. Tappable, opens the matching Library tab. Own error state so one failed call doesn't blank the row.

SessionRow

Status is an icon plus a word, never color alone. A failed row can carry a one-line reason.

EmptyState

Icon, headline that names the space, one line of body, one verb-first action. Never apologize.

SkeletonLoader

Rectangular placeholder with a slow shimmer. Match the size of what will replace it. Turn the shimmer off when reduced motion is on.

Decisions and checklist

Places where this reference deliberately departs from, or tightens, the issue text.

One redirect rule

The issue redirects when "no API key stored" but shows Welcome when the onboarding flag is false. Use the flag for first launch. If a key is later missing, send the user to Settings with a banner instead of replaying onboarding.

Inline test result, not a SnackBar

A SnackBar disappears. Key errors need to stay next to the field, and rejected keys and network failures need different copy.

Model list comes from the provider

The hardcoded IDs in the issue (for example claude-3-5-sonnet-20241022) will go stale. Fetch the list once the key validates, and keep a custom model ID fallback.

Engine address and token

The issue defaults LOOM_ENGINE_URL to http://localhost:7070. ARCHITECTURE.md says the engine picks an ephemeral port and requires a per-launch token on every request. Fine for development, but give api_client and sse_service a token parameter now, and design for the "engine starting" and "unreachable" states above.

New-user dashboard

Three zero counts tell a new user nothing. Show the setup checklist until the first skill, tool, and agent exist, then switch to the stat cards.

Minimum window size

The issue says "desktop-width" without a number. Set 960 × 640 in the macOS runner so the rail and content never collapse.
